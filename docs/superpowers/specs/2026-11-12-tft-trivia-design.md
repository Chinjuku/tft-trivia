# TFT Trivia: Design

วันที่: 2026-11-12 · สถานะ: รออนุมัติ (ผ่าน builder check แล้ว)

> **เครื่องหมาย [call]** = สิ่งที่ Claude ตัดสินใจแทน ผู้ใช้แย้งได้ ส่วนที่ไม่มีเครื่องหมายคือสิ่งที่ผู้ใช้เลือกเอง

## 1. เป้าหมายและเหตุผล

เว็บเกมทายข้อมูล Teamfight Tactics (TFT) ครอบคลุมทุก Set (Set 1 ถึงปัจจุบัน) **ไว้เล่นเองและเล่นกับกลุ่มเพื่อน** ความสนุกหลักมาจากการแข่งกันในกลุ่ม ผ่านลิงก์ท้าเพื่อนและ Quiz ประจำวัน ไม่ใช่ผลิตภัณฑ์สำหรับคนทั่วไป

### Goals
- เล่น Quiz ได้ 4 โหมด ได้แก่ Champion, Item, Trait และ Set (ทายว่าอยู่ Set ไหน)
- มี **โหมดทายปริศนา** แบบ Wordle ที่ทายด้วยการเทียบคุณสมบัติ สำหรับ Champion, Item และ Trait
- ตอบได้ 3 แบบ คือเลือกตอบ 4 ตัวเลือก พิมพ์ตอบ และผสม
- เลือกได้ว่าจะเล่นทุก Set หรือเฉพาะบาง Set
- **ลิงก์ท้าเพื่อน:** เพื่อนที่เปิดลิงก์ได้คำถามชุดเดียวกันเป๊ะ และเทียบคะแนนกันได้
- **Daily:** ทุกคนได้ชุดเดียวกันในวันเดียวกัน
- เล่นได้ทั้ง desktop และมือถือ

### Non-goals
- ไม่มี database ไม่มี backend ไม่มี login
- ไม่มี leaderboard ออนไลน์ ไม่มี multiplayer แบบ real-time
- ไม่มีหน้า admin ถ้าต้องแก้ข้อมูลก็แก้ไฟล์ JSON ตรงๆ
- ไม่มีระบบกันโกง เพราะเล่นกันเองในกลุ่มเพื่อน คำตอบอยู่ฝั่ง client ได้

### Anti-goals (ถึงจะใช้งานได้ แต่ถือว่าล้มเหลว)
- **คำถามหรือเฉลยผิด** เช่น ตัวเลือกถูกมากกว่าหนึ่งข้อ หรือตัวละครไม่ได้อยู่ใน Set ที่ระบุ เกมแบบนี้เพื่อนจะเลิกเชื่อทันที
- **ลิงก์ท้าเพื่อนได้คำถามคนละชุดกับคนที่ส่งมา**
- **ดูเหมือนผลิตภัณฑ์ทางการของ Riot** เช่น ใช้โลโก้ หรือไม่บอกว่าเป็น fan project

## 2. ข้อจำกัด
- เป็นเว็บ static ล้วน ฝากบน Vercel หรือ GitHub Pages ได้ฟรี
- ทำตาม Riot "Legal Jibber Jabber" ใช้รูปเกมได้ แต่ห้ามใช้โลโก้ TFT หรือ Riot และห้ามใช้ฟอนต์ของ Riot ต้องมีข้อความท้ายหน้าว่าเป็น fan project ที่ Riot ไม่ได้รับรอง
- ข้อมูลเกมมาจาก CommunityDragon ที่ `raw.communitydragon.org/<patch>/cdragon/tft/en_us.json`
  - ตรวจแล้ว: มีย้อนถึงแพตช์ 9.14 (Set 1 มี Champion 51 ตัว, Trait 23, Item 46) ล่าสุดคือ 16.22
  - **ไฟล์ของแต่ละแพตช์มีข้อมูลแค่ Set ที่เปิดอยู่ตอนนั้น** Set เก่าในไฟล์จะว่าง ต้องเลือกแพตช์หนึ่งให้แต่ละ Set
  - รูปแบบไฟล์เปลี่ยนไปตามเวลา ไฟล์เก่ามีแค่ `sets` ไฟล์ใหม่มี `setData` เพิ่ม ชื่อ field ต่างกันบ้าง
  - ในข้อมูลมีตัวที่ผู้เล่นซื้อไม่ได้ปนอยู่ เช่น summon และ PvE (ตัวอย่าง Voidspawn ใน Set 11 ที่ไม่มี trait) ต้องกรองออก
  - path รูปในไฟล์เป็น `.dds` แต่ CommunityDragon มี `.png` ให้ด้วยถ้าเขียน path เป็นตัวพิมพ์เล็กและเปลี่ยนนามสกุล (ทดสอบแล้ว 1 รูป)

## 3. Approaches

| ทาง | ข้อดี | ข้อเสีย |
|---|---|---|
| **Vite + React + TypeScript (เลือกทางนี้)** | ทำงานในเบราว์เซอร์ล้วน ตรงกับงานที่ไม่มี server ตั้งค่าน้อย build เร็ว | ถ้าจะเพิ่ม backend วันหลังต้องต่อ Supabase เอง |
| Next.js static export (แผนเดิมของ ChatGPT) | มี routing และ API routes พร้อม ถ้าวันหน้าจะทำ backend | ตอนนี้ไม่ได้ใช้ความสามารถฝั่ง server เลย มีแต่ขั้นตอนตั้งค่าที่เพิ่มขึ้น |
| HTML + JavaScript ล้วน | เบาที่สุด | มีทั้งหลายโหมด ช่องพิมพ์ตอบ และระบบรหัสชุดคำถาม พอโค้ดโตจะดูแลยากเพราะไม่มี type |

ผู้ใช้เลือก **Vite + React + TypeScript**

ส่วนที่ Claude เลือกให้ [call]:
- Tailwind CSS
- react-router ใช้ hash router เพื่อให้ GitHub Pages เปิดลิงก์ลึกได้
- Vitest สำหรับเทสต์
- Zod ใช้เช็กข้อมูลในสคริปต์ดึงข้อมูล

## 4. ข้อมูล

### 4.1 สคริปต์ดึงข้อมูล (`scripts/data/`, Node + TypeScript, รันมือ)
1. **`patches.ts`:** ตาราง Set → แพตช์ที่ใช้ดึง [call] ใช้แพตช์ท้ายๆ ของแต่ละ Set เพราะข้อมูลนิ่งที่สุด
   - ตัวอย่าง: Set 1 ใช้ 9.21 หรือ 9.14, Set 4 ใช้ 10.19 ส่วน builder หาแพตช์ที่ถูกต้องให้ครบ
   - Mid-set (3.5, 4.5, 7.5 …) **นับเป็น Set แยก** (ผู้ใช้เลือก) ใช้รหัสอย่าง `"4.5"`
   - ไม่รวม Set แบบ revival และโหมดจำกัดเวลา [call]
2. **Fetch:** โหลดไฟล์ดิบเก็บไว้ใน `scripts/data/raw/` ไม่ commit
3. **Parse + normalize:** อ่านรูปแบบเก่ากับใหม่ แล้วแปลงเป็นรูปแบบกลางตาม 4.2 ทำงานดังนี้
   - กรองตัวที่ผู้เล่นซื้อไม่ได้ออก
   - แปลง path รูปให้เป็น URL `.png`
   - ทำความสะอาดคำอธิบาย ลบ tag และแทนตัวแปร ถ้าทำไม่ได้ให้ตัดทิ้ง
4. **Merge tags:** เอาข้อมูลจาก `data-src/champion-tags.json` มาเติม (ดู 4.3)
5. **Validate:** ใช้ Zod และกฎตาม 4.4
6. **Write:** เขียนไฟล์ลง `public/data/v<dataVersion>/` (มี `manifest.json`, `champion-identities.json` และ `sets/set-<id>.json`) แล้ว commit ไฟล์เหล่านี้ [call]
   - **เก็บข้อมูลแยกโฟลเดอร์ตามเวอร์ชัน และไม่ลบเวอร์ชันเก่า** loader โหลดตามค่า `v` ในลิงก์ ลิงก์ท้าเก่าและ Daily ย้อนหลังจะได้คำถามชุดเดิมเป๊ะ
   - `public/data/latest.json` ชี้ว่าเวอร์ชันล่าสุดคือเลขอะไร
   - Daily ของแต่ละวันใช้เวอร์ชันล่าสุดที่มีอยู่ตอน 00:00 เวลาไทย เก็บไว้เป็นตาราง `dailyVersions` ใน `latest.json`
   - **Item ที่รวม** [call] ได้แก่ ชิ้นส่วน, ไอเทมเต็ม, Emblem, Artifact/Ornn, Radiant และ Support
   - **Item ที่ไม่รวม** ได้แก่ Augment, Charm, Anomaly, Portal และไอเทมกลไกเฉพาะ Set
   - ไฟล์ CommunityDragon รวม Item ของทุก Set ไว้ในรายการเดียว builder ต้องหาวิธีระบุว่า Item ไหนอยู่ Set ไหน เช่น ดูจาก prefix ของ apiName หรือจาก Item ที่ใช้งานในแพตช์นั้น แล้วเทียบผลกับจำนวนที่เจอจริงในเกม
- เพิ่ม Set ใหม่ = เพิ่มแถวใน `patches.ts` แล้วรันสคริปต์ใหม่

### 4.2 รูปแบบไฟล์

```ts
// manifest.json
{ dataVersion: number,           // เพิ่มขึ้นทุกครั้งที่ข้อมูลเปลี่ยน (ใช้ในลิงก์ท้า)
  sets: [{ id: "4.5", number: 4.5, name: "Fates: Festival of Beasts", patch: "10.19",
           status: "verified" | "draft", counts: { champions, items, traits } }] }

// set-<id>.json
{ id, number, name, patch,
  champions: [{ key: "TFT4_Garen",       // apiName เฉพาะของ Set
                identity: "garen",        // ใช้จับคู่ตัวเดียวกันข้าม Set
                name, cost, traits: [traitKey], range: number,
                damageType?: "AD"|"AP", role?: "Tank"|"Fighter"|"Caster"|"Carry"|"Reaper"|…,
                image, icon }],
  traits:   [{ key, name, type?: "origin"|"class"|"unique", breakpoints: number[],
               championKeys: [], icon }],
  items:    [{ key, name, kind: "component"|"completed"|"emblem"|"artifact"|"radiant"|"other",
               recipe?: [componentKey, componentKey], stats: string[], unique: boolean, icon }] }

// champion-identities.json (สร้างจากสคริปต์ รวมทุก Set)
{ [identity]: { name, gender, species, region, sets: [setId] } }
```
- เฉพาะ Set ที่ `status: "verified"` ถึงจะโผล่ในหน้าเลือก Set เปลี่ยนเป็น verified หลังเช็กตาม 4.4 และสุ่มดูด้วยตา
- Champion ที่กลับมาหลาย Set มี `identity` เดียวกัน แต่แต่ละ Set มี record ของตัวเอง เพราะ cost, trait และ role ต่างกัน

### 4.3 ข้อมูลที่ต้องเติมเอง (`data-src/champion-tags.json`)
ในไฟล์ TFT ไม่มีข้อมูลเพศ เผ่าพันธุ์ และภูมิภาค แต่โหมดทายปริศนาต้องใช้ จึงเติมแยกตาม identity

| ข้อมูล | แหล่ง |
|---|---|
| range: ประชิดหรือไกล | คำนวณจาก `stats.range` ในข้อมูล TFT ได้ทุก Set [call] ค่า ≤ 1 = ประชิด |
| damageType + role | ข้อมูล TFT มีฟิลด์ `role` เช่น `ADCarry`, `APTank` ใน Set ใหม่ (เจอใน Set 11 แต่ไม่มีใน Set 1) Set เก่าที่ไม่มีให้ใช้ `adaptiveType` และ `roles` ของ LoL จาก Meraki Analytics (`cdn.merakianalytics.com/riot/lol/resources/latest/en-US/champions/<Name>.json`) แทน แล้ว**แปลงให้เป็นคำเรียกแบบ TFT** [call] Marksman→Carry, Mage→Caster, Tank→Tank, Fighter/Juggernaut→Fighter, Assassin→Reaper, Support/Enchanter→Caster และแก้ทับทีละตัวได้ใน `champion-tags.json` (`roleOverrides[setId]`) |
| region | `faction` จาก Meraki ตัวไหนไม่มีก็เติมเอง |
| gender, species | **เติมเอง** ได้ทีละ identity ร่างค่าให้ก่อนได้ แต่ต้องตรวจทุกแถว |

- ตัวที่มีแค่ใน TFT ไม่มีใน LoL (เช่นมังกรใน Set 7) ไม่มีใน Meraki ต้องเติมเองทั้งหมด
- **ค่าที่ใช้ได้** [call]
  - gender: ชาย, หญิง, อื่นๆ/ไม่ระบุ
  - species: มนุษย์, Yordle, Vastaya, Void, Undead, Darkin, Celestial/Spirit, Dragon, Golem/Construct, สัตว์/Monster, อื่นๆ
- **ใครเติมและตรวจ** [call]
  - builder ร่างค่าให้ทุก identity แต่ละแถวมี `reviewed: false`
  - ทำหน้ารีวิวสำหรับ dev เท่านั้น (`/#/review` ไม่แสดงใน production) ไว้ให้ผู้ใช้ไล่ยืนยันหรือแก้ทีละตัว แล้ว export เป็น JSON กลับมาแทนไฟล์เดิม
- **ขั้นต่ำก่อน deploy** [call] Quiz ทั้ง 4 โหมดต้องเล่นได้ทุก Set ที่ verified
  - โหมดทายปริศนาและทาย Champion ประจำวันจะเปิดก็ต่อเมื่อ identity ที่ `reviewed: true` มีอย่างน้อย 80% ของทั้งหมด
- ถ้า identity ไหนข้อมูลยังไม่ครบหรือยังไม่ได้ตรวจ ตัวนั้นยังเป็นคำตอบของโหมดทายปริศนาไม่ได้ แต่ยังพิมพ์ทายได้ และช่องที่ไม่มีข้อมูลจะแสดงเป็น "?"

### 4.4 กฎตรวจข้อมูล (ไม่ผ่านแล้วสคริปต์หยุด)
- ทุก Champion มีชื่อ, cost 1–5 (หรือค่าพิเศษที่ระบุไว้) และ trait อย่างน้อย 1 ตัว
- trait ที่ Champion อ้างถึงต้องมีจริงใน Set เดียวกัน
- ใน Set เดียวกัน ชื่อ Item และชื่อ Champion ต้องไม่ซ้ำ
- จำนวนตัวในแต่ละประเภทต้องอยู่ในช่วงที่สมเหตุสมผล [call] Champion 45–110 ตัวต่อ Set เป็นตัวเลขตั้งต้น
- รูปทุกรูปเปิดได้จริง (HTTP 200) เช็กครั้งเดียวตอนรันสคริปต์ รูปที่เปิดไม่ได้ให้บันทึกไว้ ไม่ต้องหยุดสคริปต์

## 5. โหมดเกม

### 5.1 Quiz (10 ข้อต่อรอบ [call], 20 วินาทีต่อข้อ [call])

| โหมด | คำถาม | คำตอบ |
|---|---|---|
| Champion | แสดงรูปตัวละคร | ชื่อ |
| Item | แสดงไอคอน Item และสูตร (ถ้ามี) สุ่มว่าจะโชว์อย่างไหน | ชื่อ |
| Trait | แสดงไอคอน Trait หรือรายชื่อตัวละครใน Trait | ชื่อ |
| Set | แสดง Champion พร้อม trait ของ Set นั้น หรือแสดง Trait | ตัวละครหรือ Trait นี้อยู่ Set ไหน |

- **ตัวเลือกหลอก:** มาจาก Set ที่เลือกเล่นและเป็นประเภทเดียวกัน ห้ามมีคำตอบถูกมากกว่าหนึ่งข้อ
  - ตัวอย่าง: โหมด Set ห้ามใช้ Set ที่มีตัวละคร (identity เดียวกัน) หรือ Trait ชื่อเดียวกันเป็นตัวหลอก ข้อนี้สำคัญมากเพราะ mid-set ใช้ตัวละครกับ Trait ซ้ำกับ Set หลักเยอะ
    - เช่น ถาม Garen ใน Set 4 ตัวหลอกจะเป็น 4.5 ไม่ได้ ถ้า Garen ก็อยู่ใน 4.5 ด้วย
    - ถ้าหาตัวหลอกที่ถูกต้องไม่ครบ 3 ตัว ให้ทิ้งคำถามแล้วสุ่มใหม่ด้วย seed เดิม ต้องได้ผลเหมือนเดิมทุกเครื่อง
  - ตัวอย่าง: ถ้ามี Item ชื่อซ้ำข้าม Set และรูปเหมือนกัน ให้นับเป็นคำตอบเดียวกัน
- **ไม่ถามซ้ำในรอบเดียวกัน** ใช้ identity เป็นเกณฑ์ ไม่ใช่ key ของแต่ละ Set
- **แบบผสม:** สุ่มต่อข้อ [call] 60% เลือกตอบ / 40% พิมพ์ตอบ ส่วนโหมด Set ใช้เลือกตอบเสมอ
- **การตรวจคำตอบที่พิมพ์:**
  - ตัดตัวพิมพ์เล็กใหญ่ เว้นวรรค จุด ' และ - ออกก่อนเทียบ
  - มีตาราง alias เช่น `j4` → Jarvan IV, `ie` → Infinity Edge
  - [call] พิมพ์ผิดได้ 1 ตัวอักษรถ้าชื่อยาวเกิน 6 ตัว
- **คะแนน:** ตอบถูกได้ 100 + โบนัสความเร็ว 0–50 (ลดลงเป็นเส้นตรงตามเวลาที่ใช้) [call] ตัด multiplier ตามระดับความยากออก ไม่มีหน้าเลือกความยาก

### 5.2 ทายปริศนา (Champion / Item / Trait)
- สุ่มตัวที่เป็นคำตอบหนึ่งตัวจาก Set ที่เลือก ผู้เล่นพิมพ์ชื่อโดยมี autocomplete ช่วย
  - รายการใน autocomplete คือ "ชื่อ · Set N" เพราะคำตอบคือตัวละครหรือ Item **ของ Set นั้นๆ**
- ทายแต่ละครั้งได้แถวผลลัพธ์ แต่ละช่องเป็นสีเขียว (ตรง), เหลือง (ตรงบางส่วน) หรือแดง (ไม่ตรง) ถ้าเป็นตัวเลขจะมีลูกศรบอกว่าคำตอบสูงหรือต่ำกว่า
- **ทายได้ไม่จำกัด** คะแนนคือจำนวนครั้งที่ใช้ ยิ่งน้อยยิ่งดี [call] มีปุ่มยอมแพ้
- **คอลัมน์ของ Champion:**
  - เพศ, เผ่าพันธุ์, ระยะ, AD/AP, บทบาท, ภูมิภาค
  - Cost (↑↓)
  - Traits: เหลืองถ้ามีตรงกันบางตัว
  - Set (↑↓): เขียวถ้า Set เดียวกัน, เหลืองถ้า identity เดียวกันแต่อยู่คนละ Set
- **คอลัมน์ของ Item:**
  - ประเภท (kind)
  - สูตร: เหลืองถ้ามีชิ้นส่วนตรงกัน 1 ชิ้น
  - สเตตัส: เหลืองถ้ามีตรงกันบางตัว
  - Set (↑↓), unique
- **คอลัมน์ของ Trait:**
  - ประเภท
  - Set (↑↓)
  - จำนวนตัวละคร (↑↓), จำนวนขั้น (↑↓), ขั้นแรก (↑↓)
  - Cost ของตัวละครใน Trait: เหลืองถ้าช่วง cost ซ้อนกัน
- ถ้าข้อมูลของ Set ไหนไม่มีฟิลด์ใด ช่องนั้นแสดงเป็น "?" และนับว่าไม่ตรง

### 5.3 รหัสชุดคำถาม: ลิงก์ท้าเพื่อนและ Daily
- ใช้ PRNG ที่ให้ผลเหมือนเดิมทุกครั้ง เช่น mulberry32 ร่วมกับ hash ของ string [call] **ห้ามใช้ `Math.random`** ในส่วนที่สร้างคำถาม
- `generate(config, seed, data)` ต้องเป็น pure function รับค่าชุดเดียวกันต้องได้ผลเหมือนกันทุกเครื่อง
  - เรียงข้อมูลตาม key ก่อนสุ่มเสมอ เพื่อให้ผลไม่ขึ้นกับลำดับในไฟล์
  - ข้อที่ถามแบบพิมพ์ในโหมดผสมก็ต้องมาจาก seed ด้วย
- **ลิงก์ท้าเพื่อน:** `#/c?v=<dataVersion>&m=<mode>&s=<sets>&a=<style>&seed=<seed>&n=<ชื่อเล่น>&sc=<คะแนน>`
  - ใช้ได้ทั้ง Quiz และทายปริศนา
  - ถ้า `v` ไม่ตรงกับ `dataVersion` ปัจจุบัน ให้ขึ้นเตือนว่าข้อมูลเปลี่ยนแล้ว คำถามอาจไม่ตรง แต่ยังให้เล่นได้ [call]
  - [call] คะแนนในลิงก์เป็นตัวเลขธรรมดา ไม่ต้องเข้ารหัส เพราะไม่กันโกง
- **Daily:** seed คือ `daily-YYYY-MM-DD` ตามเวลาไทย (UTC+7) [call] มี 2 อย่างต่อวัน
  1. Daily Quiz 10 ข้อ คละทั้ง 4 โหมดจากทุก Set ที่ verified แล้ว
  2. ทาย Champion ประจำวัน
  - แต่ละเครื่องเล่นได้วันละครั้งต่ออย่าง (ไม่ได้ป้องกันจริงจัง) Daily ใช้ dataVersion ณ วันนั้น
- **แชร์ผล Daily:** คัดลอกข้อความแบบนี้ไปแปะในแชต `TFT Trivia 12 พ.ย. 7/10 🟩🟩🟥🟩…`

### 5.4 ข้อมูลที่เก็บในเครื่อง (localStorage)
- เก็บ ชื่อเล่น, ค่าที่ตั้งไว้ล่าสุด, คะแนนดีที่สุดแยกตามโหมด, ผล Daily และจำนวนวันที่เล่นต่อเนื่อง
- ห่อทุกครั้งที่อ่านหรือเขียนด้วย try/catch ถ้า localStorage ใช้ไม่ได้ เกมยังต้องเล่นได้

## 7. โครงสร้างโค้ด (แนวทาง)
```
src/
  data/        loader (fetch manifest + set ที่เลือก, cache), types
  engine/      rng.ts, quiz.ts (generate), guess.ts (compare), answer.ts (normalize/alias/fuzzy), score.ts
  features/    home/, quiz/, guess/, result/, challenge/
  lib/storage.ts
scripts/data/  patches.ts, fetch.ts, normalize.ts, validate.ts, write.ts
data-src/      champion-tags.json, aliases.json
public/data/   manifest.json, champion-identities.json, sets/*.json
```
- engine ต้องไม่รู้จัก React และไม่ fetch เอง ให้รับข้อมูลเข้ามาเป็น argument เพื่อให้เทสต์ง่าย
- **เทสต์ที่ต้องมี:**
  - seed เดียวกันได้ชุดคำถามเดียวกัน
  - ตัวเลือกถูกมีข้อเดียวเสมอ ให้รัน generate หลายพันรอบกับข้อมูลจริง
  - ไม่มีคำถามซ้ำในรอบเดียวกัน
  - ฟังก์ชัน compare ของทายปริศนาให้ผลถูกในทุกคอลัมน์
  - การ normalize คำตอบและ alias
